# QA 의도 원장 (템플릿)

> 이 파일을 대상 레포의 `.crew/qa-intent-ledger.md`로 복사해 쓴다. qa-audit은 실행 시작 때 이 파일을 읽고, 실행이 끝나면 새 결정·지적을 기록하도록 요청한다.
> 아래 예시 행은 형식 안내용이다 — 복사한 뒤 지운다.

## ① 의도 결정

감사가 "결함인가, 의도된 차이인가"를 물었고 사람이 답한 항목. **여기 기록된 항목은 다음 실행에서 다시 묻지 않는다.** 규칙 근거가 된 원천(디자인 문서·데이터 출처)이나 해당 위치의 구조가 바뀐 항목만 다시 확인한다.

| 규칙·위치 | 결정 | 결정자 | 날짜 | 근거 |
|---|---|---|---|---|
| `<규칙 ID 또는 확인 항목>` · `<파일:줄 또는 화면 경로·요소>` | `intended` | `<이름 또는 역할>` | `<YYYY-MM-DD>` | `<왜 의도된 차이인가 — 디자인 문서 절, 코드 주석 위치 등>` |

- 결정 값: `intended`(의도된 차이 — 결함 아님) / `bug`(결함 — 수정 대상) / `next-phase`(결함이지만 이번 범위 밖 — 다음 단계에서 처리)
- `bug`·`next-phase`는 이슈·태스크 링크를 근거 열에 함께 적는다.
- 원천·구조가 바뀌어 다시 확인한 경우 새 행을 추가하고 이전 행은 지우지 않는다(이력 보존).

## ② 놓친 결함 (골든셋)

감사 결과에는 없었고 **사용자 리뷰에서만 나온 지적**을 기록한다. 하네스가 무엇을 놓치는지 보여주는 골든셋이며, 다음 실행에서 같은 결함을 잡는지 재현 확인에 쓴다.

| 날짜 | 화면 | 사용자 지적 | 반영 위치 | 재현 확인 |
|---|---|---|---|---|
| `<YYYY-MM-DD>` | `<경로 · viewport>` | `<지적 원문 요약 — 예: 같은 기능인데 화면마다 목록 페이지 이동 방식이 다름>` | `<프로필 규칙 / 축 문서 / 수동 확인 표 / 반영 안 함(사유)>` | `<다음 실행에서 검출됨 / 미검출 / 미실행>` |

- 한 프로젝트에만 해당하는 지적은 `.crew/qa-profile.md`·`.crew/qa-profile.json`에 반영한다.
- 다른 프로젝트에도 일반화할 수 있는 지적이면 하네스 개선 요청(hr-agent)을 올리고, 반영 위치 열에 요청 링크를 적는다.
- 재현 확인이 `미검출`로 남은 항목은 다음 회고에서 다룬다.

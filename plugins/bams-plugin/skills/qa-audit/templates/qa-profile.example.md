# QA 프로필 — 사람 판정 기준 (템플릿)

> 이 파일을 대상 레포의 `.crew/qa-profile.md`로 복사해 `<…>` 자리를 채운다. 기계가 읽는 설정은 `.crew/qa-profile.json`(템플릿 `qa-profile.example.json`, 스키마 `references/qa-profile.md`)이 맡고, 이 문서는 스크립트가 판정하지 못하는 기준과 작업 제약을 적는다.
> 채우지 않은 행은 지우지 말고 `해당 없음`으로 둔다. 판정 임계값은 숫자로 프로젝트가 정한다(이 템플릿은 숫자를 정하지 않는다).
> 우선순위: 레포 CLAUDE.md·`.crew/` 규칙 > 이 문서 > qa-audit 기본값.

## 1. 디자인 시스템(DS) 카테고리

자동 정합 단계(스크립트 + `project_checks`)와 함께 사람이 화면·코드를 보고 확인한다. 위반은 "근거" 열에 적힌 사실이 확인될 때만 결함으로 올린다. 의도된 차이면 코드 주석(작업명·날짜·의도·영향 범위)을 확인하고 `.crew/qa-intent-ledger.md` ①에 기록한다.

| 카테고리 | 확인 사항 | 위반 판정 근거 |
|---|---|---|
| 상단 영역 | `<상단 바·제목 영역에 남겨야 할 요소 / 제거할 장식 요소>` | `<같은 정보가 상단과 본문 첫 블록에 중복 노출>` |
| 간격 리듬 | `<블록 사이 간격 토큰 — 예: 제목→본문, 묶음 사이>`, `<간격을 부모 gap으로 줄지 개별 margin으로 줄지>` | `<토큰 밖 간격 값 또는 금지된 간격 방식 사용>` |
| 카드/묶음 | `<묶음 단위 공유 컴포넌트 이름과 위치>`, `<내부 값 표시 컴포넌트와 그 용도(숫자 전용 등)>` | `<교체 가능한데 공유 컴포넌트 대신 손코딩 / 카드 안에 카드가 겹쳐 보임>` |
| 배지/칩 | `<정적 라벨용 공유 컴포넌트>`, `<인터랙티브 트리거(토글·정보 아이콘)는 별도 컴포넌트를 쓰는지>` | `<인터랙티브 요소가 정적 라벨 컴포넌트를 사용>` |
| 공유 컴포넌트 교체 | `<손코딩 패턴 → 대응 공유 컴포넌트 매핑 — 예: 뒤로가기·원문 링크 버튼, 접이식 영역, 필터 탭>` | `<대응 공유 컴포넌트가 있는데 소비하지 않음>` |
| radius 위계 | `<외곽 / 내부 / 칩 단계별 radius 토큰 이름>` | `<안쪽 요소의 radius가 바깥보다 큼, 토큰 밖 값>` |
| 인라인 style | `<허용 조건 — 예: 런타임 동적 값만, 허용 목록 위치>` | `<허용 목록 밖 인라인 style>` |
| 목록/행 | `<행 형태(평면·hover 배경 등)>`, `<값 정렬 기준>`, `<반복 라벨 처리>` | `<같은 목록 안 정렬·형태 불일치>` |
| 차트 | `<같은 화면 안 차트 시각 통일 기준>`, `<라벨을 SVG가 아닌 HTML로 그리는지 등 왜곡 방지 규칙>` | `<같은 화면 차트 간 시각 불일치, 늘어난 텍스트>` |
| 중복/저정보 배지 | `<숨길 대상 — 예: 제목과 같은 내용, 데이터가 있다는 사실만 알리는 상태 표시>` | `<정보가 중복되거나 새 정보가 없는 배지·칩 노출>` |
| 기본 a11y | `<공유 컴포넌트가 보장하는 범위>`, `<손코딩 트리거에서 직접 확인할 항목 — 접근 가능한 이름, 키보드 포커스 표시>` | `<손코딩 트리거의 이름·포커스 표시 누락>` (세부 판정은 a11y 축 문서) |

필요한 카테고리를 행으로 추가한다. 공유 컴포넌트 목록·위치는 `qa-profile.json`의 `ui_dir`·`ui_wrappers`·`page_structure`와 같은 이름을 쓴다.

## 2. 프로세스 제약

감사·수정 작업이 지켜야 하는 제약. 위반은 결과물과 별개로 fail로 기록한다. 기계 판정 가능한 금지 작업 요약은 `qa-profile.json`의 `forbidden_ops`에도 넣는다.

| # | 제약 | 프로젝트 값 |
|---|---|---|
| 1 | **프리뷰 격리** — 프로덕션 파일을 바로 고치지 않고 버릴 수 있는 프리뷰 경로에서 반복·검증한 뒤 이관하고 프리뷰는 삭제한다 | `<프리뷰 경로 규칙 — 예: <route>-preview>` |
| 2 | **페이지별 브랜치** — 페이지 하나에 브랜치 하나. 기본 브랜치에 직접 커밋·PR 금지 | `<브랜치 이름 규칙>` |
| 3 | **데이터 계층 미접촉** — UI QA 작업은 데이터 조회·가공 계층을 수정하지 않는다 | `<손대지 않을 경로 목록>` |
| 4 | **공유 컴포넌트 수정** — 수정은 사전 경고 + 명시 허락 후에만. 슬롯·props로 소비하는 것은 자유 | `<허락 주체>` |
| 5 | **신규 공유 컴포넌트** — 바로 추가하지 않고 승격 후보로 등록한 뒤 결정한다 | `<승격 후보 문서 경로>` |
| 6 | **목업은 참고용** — 목업 값이 아니라 프로덕션 토큰을 쓰고, 의도된 차이는 코드 주석으로 남긴다 | `<목업·디자인 문서 위치>` (`qa-profile.json` `design_docs`) |

감사자는 read-only가 기본이다 — 판정과 수정 요청까지만 하고, 직접 고칠 때는 1번 격리를 거친다.

## 3. 표기 규칙

같은 화면이 여러 데이터 출처를 함께 보여줄 때, 한 출처의 문구·서식이 다른 출처 화면에 그대로 남아 있는지 사람이 대조한다(자동화하지 않는다). 확정된 규칙은 `qa-profile.json`의 `notation_rules`에 `{scope, rule}`로 옮긴다.

| 확인 항목 | 대조 기준 (자리표시자) |
|---|---|
| 서식·문서 유형명 | `<출처 A에서 쓰는 서식명>` ↔ `<출처 B에서 쓰는 서식명>` — 다른 출처 화면에 섞이지 않았는가 |
| 통화·단위 | `<데이터의 통화·단위 필드>`와 화면 기호가 일치하는가 |
| 목록 안내 문구 | 안내 문구가 실제로 있는 탭·필터만 가리키는가 |
| 링크 미리보기·메타 설명 | 출처별로 맞는 설명이 나가는가 |
| 제도 기준 표현 | `<출처마다 다른 기준 표현 — 예: "이상" / "초과">`이 출처에 맞게 쓰였는가 |

## 4. 타이포 수동 확인

스크립트의 타이포 축은 `qa-profile.json` `typography` 기준으로 역할 불일치·스케일 밖 크기만 잡는다. 아래는 화면을 보고 확인한다.

| 항목 | 프로젝트 값 |
|---|---|
| 최소 글자 크기 | `<본문·보조 텍스트 하한 — 단위 포함>` |
| 줄바꿈 규칙 | `<로케일별 규칙 — 예: 한국어는 단어 단위 줄바꿈(word-break: keep-all)>` |
| 숫자 표기 | `<고정폭 숫자·정렬이 필요한 값의 종류>` |
| 잘림·말줄임 | `<말줄임 허용 위치와 전체 값 노출 방법>` |

대비는 a11y 축 측정값(실측 수치)으로 기록한다. 눈으로 본 인상으로 판정하지 않는다.

## 5. 프로젝트 검증 명령

레포 고유 검증 명령은 `qa-profile.json`의 `project_checks`(`{name, cmd, axis}`)에 등록하면 엔진이 **직렬로** 실행하고 명령과 exit 코드를 증거로 남긴다. 병렬 실행은 출력이 섞여 실패 지점을 짚을 수 없으므로 하지 않는다. 리뷰 반영으로 코드가 바뀌면 앞선 결과는 근거가 안 되므로 전부 다시 실행한다.

| name | cmd | axis | 비고 |
|---|---|---|---|
| lint | `<예: npm run lint>` | ui | |
| typecheck | `<예: npm run typecheck>` | ui | |
| `<토큰·DS 규칙 검사>` | `<명령>` | ui | `<검사 범위 — 예: 원시 색상 리터럴, 우회 클래스, 허용 목록 밖 인라인 style>` |
| `<번들·데이터 누수 검사>` | `<명령>` | perf | `<선택>` |

일시적으로 끈 검사는 지우지 말고 비고에 `비활성 — 수동 검토`로 표시하고, 그동안 사람이 같은 범위를 확인한다.

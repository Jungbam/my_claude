# 로딩·스켈레톤 체크리스트 [L2]

> `perf-audit.md` P5·P6과 `a11y-audit.md` A5에서 함께 쓴다. 관찰 전용.

기준 문장: **스켈레톤은 최종 UI의 데이터가 비어 있는 상태다. 실제 UI를 바꿔 스켈레톤에 맞추지 않는다.**

항목마다 `통과` / `결함 후보` / `해당 없음` / `미검증` 중 하나로 표시한다. 프로필 필드가 있어야 판단할 수 있는 항목은 **(프로필 필드)** 로 표시했다 — 그 필드가 없으면 그 항목은 `미검증`으로 둔다(실패도 통과도 아님).

## 구조

- [ ] 실제 UI와 스켈레톤을 같은 viewport에서 비교했다 (`skeleton-hold`).
- [ ] 같은 부모 셸(페이지 컨테이너·카드·데이터 표 등, 프로필 `page_structure`)과 같은 breakpoint를 쓴다. 섹션 전용 스타일 모듈도 재사용한다.
- [ ] 데이터가 없어도 아는 제목·설명·필터·탭·breadcrumb은 스켈레톤으로 바꾸지 않는다.
- [ ] 표 컬럼 비율·정렬(숫자 오른쪽), 이미지·로고 크기, 모바일 카드 전환이 실제와 같다.
- [ ] 구조가 다른 두 화면을 같은 큰 회색 박스나 범용 카드 grid로 합치지 않았다.
- [ ] 알 수 없는 권한·버튼·통계·행 개수를 확정해 보여 주지 않는다. 접힌 패널을 임의로 펼치지 않는다.
- [ ] 알 수 없는 전체 행 수에 맞추려고 큰 고정 높이를 넣지 않았다. 긴 내용·빈 응답에서도 깨지지 않는다.
- [ ] 결과 전용 / 필터 포함 스켈레톤을 중첩해 필터를 두 번 그리지 않는다.

## 상태와 접근성

- [ ] 가시 `role="status"` + `aria-busy`가 정확히 하나다. 하위 fallback의 가시 로딩 문장이 본문 위치를 밀지 않는다.
- [ ] 장식 placeholder는 `aria-hidden`, 숨긴 실제 컨트롤은 `inert`.
- [ ] **(프로필 `page_structure.skeleton`)** 공통 스켈레톤 컴포넌트와 reduced-motion 가드를 쓴다. 개별 화면이 펄스 애니메이션을 직접 쓰지 않는다. 문장·제목 안에서는 인라인 요소로 렌더한다.

## 최초 로딩과 재조회

- [ ] 데이터가 없을 때만 전체 스켈레톤·전체 오류를 보인다.
- [ ] **(프로필 `page_structure.refresh_notice`)** 현재 조회 키의 데이터가 있으면 재조회 실패에도 본문·카드·선택·입력 포커스·스크롤을 유지하고, 프로젝트 재조회 알림 컴포넌트로 재시도를 준다 (QA 브라우저 안 오류 주입으로 확인).
- [ ] 캐시된 SPA 재진입에서 전체 스켈레톤이 다시 뜨지 않는다 (`measure-web` `query-warm`의 `스켈레톤 재노출 = 아니오`). `query-warm`이 `미검증`이면 이 항목도 `미검증`.
- [ ] 버튼 제출·백그라운드 갱신에 화면 전체 스켈레톤을 쓰지 않는다.
- [ ] 독립 데이터는 독립적으로 로딩한다(한 섹션이 무관한 다른 섹션의 응답을 기다리지 않음). 선택적 섹션은 데이터가 없으면 만들지 않는다.
- [ ] 정상·빈 상태·오류·로딩이 별도 분기다. 빈 응답·오류·권한 미확정을 정상 데이터로 꾸미지 않는다.

## 전역 로더 (명시적 blocking 작업만)

이 절 전체가 **(프로필 `loading.*`)** 항목이다. `loading.busy_selector`·`loading.blocking_threshold_ms`·`loading.slow_ms`·`loading.overdue_ms`가 없으면 시간 기준 항목은 `미검증`이다.

- [ ] 전역 로더는 실제 작업 이름으로 열고(`show(작업 이름)` 등) 실패해도 `finally`에서 닫는다. `loading.blocking_threshold_ms` 이후에만 표시하고, 최소 노출 시간·애니메이션 완료 대기를 두지 않는다.
- [ ] `loading.slow_ms`에 지연 안내, `loading.overdue_ms`에 비차단 안내로 전환하되 로더 상태를 임의로 숨기지 않는다. 가짜 성공·자동 재시도를 만들지 않는다.
- [ ] 선택적 사전 로딩(warm-up)은 전역 로더·오류를 띄우지 않는다.

## 기록

- [ ] 인증·DB가 필요한 상태를 실제로 실행하지 못했다면 `미검증`으로 썼다.
- [ ] 프로필 필드가 없어 판단하지 못한 항목을 `미검증`으로 썼다(건너뛴 항목 수 포함).
- [ ] 보류 캡처 결과를 CLS 수치로 쓰지 않았다.
- [ ] 결함 후보는 코드(`file:line`)나 화면으로 확인한 뒤에만 결함으로 올렸다.
